> Status: **audit complete (2026-09-26)** · Owner: Alex · Execution: coding
> agent on `phase-2-3-geometry-fidelity-audit`; pre-registered spec `14fe5c3`,
> reproducible diagnostic `7dc9c8b`.
> Prereq: Phase 2.2 publicly released and closed on `main`.
> Rules: `AGENTS.md` applies. This phase authorizes inspection, reproducible
> diagnostics and documentation only. It does not authorize a solver, physical-
> units, geometry, rendering or UI correction.

## 1. Trigger

Manual QA of a NACA 2412 at the HIGH preset and +10 degrees showed a visibly
stair-stepped airfoil and an apparently detached purple cell at the trailing
edge. The maintainer's leading hypothesis is that the point is simply the last
rasterized trailing-edge cell rather than an unrelated obstacle.

The same QA also established a broader product problem: a user cannot easily
distinguish the geometry SOPLO numerically resolves from the smooth geometry it
represents, or tell how that distinction affects trust in the result.

## 2. Goal

Trace procedural NACA geometry through all four representations before any fix:

1. analytic polygon generated by `naca4()`;
2. placed and rotated lattice polygon;
3. `solid=2` raster mask consumed by the LBM solver;
4. Canvas and streamline presentation of that mask.

The output is an evidence-backed classification of each observed discrepancy
and a bounded implementation decision for the next phase.

## 3. Static findings that require measurement

The initial code trace found three discrepancies. They are findings to verify,
not permissions to edit the implementation.

### F1 — NACA reference length and rasterized chord differ

`NACA_CHORD_CELLS` defines LOW/MED/HIGH as 20/40/80 cells, and
`geometryCharCells()` supplies that value to physical-to-lattice conversion,
force normalization and Strouhal estimation. `buildSimulation()`, however,
places the NACA polygon with `RESOLUTION_CELLS`: 10/20/40 cells. The settings UI
also displays 10/20/40.

If the rasterized extent follows the placement width, the solver metadata uses
approximately twice the chord actually represented by the mask. That would be
physics-adjacent, not cosmetic:

- lattice viscosity and τ are derived with twice the actual chord;
- the flow Reynolds number based on the represented chord is approximately
  half the displayed physical Reynolds number;
- Cd/Cl reference length and any NACA Strouhal value use twice the represented
  chord.

No correction is authorized in this audit. A confirmed mismatch triggers a
separate physical-correction spec and revalidation plan.

### F2 — Aerodynamic solids are rendered as field cells

`Canvas2D` assigns the explicit solid colour only when `solid[k] === 1`.
Aerodynamic bodies are encoded as `solid=2`, so their cells pass through the
active-field colormap. In the velocity-magnitude view their near-zero values
appear purple and bilinear upscaling softens the cell boundaries. This can make
the numerical mask look like part of the flow field.

### F3 — Streamlines ignore aerodynamic-solid encoding

`StreamlineRenderer.step()` respawns a particle only for `solid === 1`. A
particle entering a `solid=2` aerodynamic body is therefore not rejected by the
mask check. Whether its interpolated zero velocity merely stalls it or lets its
trail cross the body must be observed, but the encoding contract is already
inconsistent with the solver's `solid !== 0` treatment.

## 4. Pre-registered predictions

These predictions are written before running the diagnostic matrix.

1. **Trailing-edge hypothesis:** the apparent point belongs to the NACA mask
   and lies at its maximum-x end. It may be separated under 4-neighbour
   connectivity while remaining attached under the D2Q9 8-neighbour stencil.
2. **Resolution mismatch:** measured solid-mask chord will track approximately
   10/20/40 cells while run metadata reports 20/40/80.
3. **Angle sensitivity:** the trailing-edge topology will vary with rotation
   because cell-centre point-in-polygon sampling can skip a sub-cell-thickness
   section of the taper.
4. **Thickness sensitivity:** thinner NACA 0006/0009 profiles will show more
   disconnected or one-cell-wide trailing-edge topology than 0012/0015 at the
   same chord resolution.
5. **Presentation mismatch:** the screenshot's purple body is the zero end of
   the active colormap, not an explicit aerodynamic-solid visual layer.

A failed prediction is recorded; thresholds or implementation are not changed
to make it pass.

## 5. Diagnostic matrix

Run headlessly against the unchanged builder:

- profiles: every committed `NACA_OPTIONS` value;
- resolutions: LOW, MEDIUM and HIGH;
- angles: -15, -10, -5, 0, +5, +10 and +15 degrees;
- exact reported case: NACA 2412, HIGH, +10 degrees.

For each case record:

- metadata `charCells`;
- mask bounding-box width and height;
- aerodynamic-solid cell count;
- number and size of 4-neighbour connected components;
- number and size of 8-neighbour connected components;
- coordinates and component membership of the maximum-x cells.

The 8-neighbour result is the relevant connectivity observation for D2Q9, but
the 4-neighbour result remains useful for explaining the visual gap.

## 6. Classification rules

- **Expected discretization:** one 8-connected body; any visually detached tip
  is part of that component and the represented reference length is coherent.
- **Presentation defect:** the solver mask is coherent but Canvas or streamline
  logic contradicts the `solid=1` / `solid=2` encoding contract.
- **Geometry defect:** the polygon or rasterizer creates multiple 8-connected
  body components or unintended isolated cells.
- **Physical-mapping defect:** metadata/reference length materially differs
  from the measured procedural geometry extent.

No category may be softened to “cosmetic” when it affects τ, Reynolds number,
force normalization, frequency normalization or the cells seen by the solver.

## 7. Required evidence and stop condition

The audit is complete when:

1. the full matrix and exact QA case are reproducible;
2. F1–F3 are classified with measured evidence;
3. `PLAN_OF_ATTACK.md` and `PROJECT_CONTEXT.md` identify the next bounded phase;
4. no protected solver/physics file, test gate or acceptance window changed;
5. the repository remains clean and the existing 62-test fast suite remains
   green.

If F1 is confirmed, this phase stops after documentation. The next phase must
specify the intended NACA chord convention, migration impact, focused tests and
the validation required before any code change.

- Tritton, *Physical Fluid Dynamics*: physical interpretation and user-facing
  flow explanations; edition and exact pages must be confirmed before external

- Oberkampf & Roy (2010), *Verification and Validation in Scientific

## 9. Measured evidence

The committed diagnostic evaluates all seven `NACA_OPTIONS`, all three
resolution presets and seven angles from -15 to +15 degrees: 147 cases. Run it
with:

```bash
node --import tsx scripts/audit-naca-geometry.ts
node --import tsx scripts/audit-naca-geometry.ts --csv
```

The complete CSV produced the identical SHA-256
`5a4f0098ab21b1de0fe328bd10263e0cda55be5673e0a1615c3fb60dff6fd47e`
under Node 20.20.2 and Node 24.15.0.

### F1 — CONFIRMED: physical-mapping defect

All 147 cases place the polygon with 10/20/40 cells while metadata reports
20/40/80. The exact QA case (NACA 2412, HIGH, +10 degrees) records:

| Quantity | Metadata / displayed model | Placed polygon |
|---|---:|---:|
| Chord resolution | 80 cells | 40 cells |
| Re for the diagnostic setup | 666.67 | 333.33 |
| Physical cell size | 0.0025 m | 0.0050 m |
| Occupied mask x-span | — | 39 cells |

The factor-two mismatch propagates into τ, the safety ceiling, Cd/Cl reference
length and Strouhal normalization. With the current implementation, NACA force
coefficients and frequency normalization must not be described as quantitative,
and the displayed Reynolds number does not describe the chord represented by
the lattice mask.

### F2 — CONFIRMED: presentation defect

The screenshot's purple body is not an explicit body layer. `Canvas2D` gives
the solid colour only to `solid=1`; `solid=2` aerodynamic cells are passed
through the active field colormap and then bilinearly enlarged. The visual
cannot currently distinguish “solid body” from “lowest field value.”

### F3 — CONFIRMED: presentation-contract defect

`StreamlineRenderer.step()` rejects only `solid=1`. It does not enforce a
collision with `solid=2` aerodynamic bodies. Interpolated zero velocity may
slow or stall some particles, but the renderer has no body-mask guarantee and
can retain trails through cells that the solver treats as solid.

### F4 — CONFIRMED: geometry defect

The maintainer's provenance hypothesis was correct: the reported point is the
maximum-x trailing-edge cell. It is not merely a display artefact, however. In
the exact QA case it is a one-cell component disconnected under both 4- and
8-neighbour connectivity, so the LBM solver sees it as a separate obstacle.

Across the matrix:

- 43/147 masks have multiple 4-neighbour components;
- 25/147 masks have multiple D2Q9-relevant 8-neighbour components;
- NACA 0006/LOW/0 degrees and 0009/LOW/0 degrees contain zero body cells;
- 0006 accounts for 14 of the 25 disconnected 8-neighbour cases;
- 0012 and 0015 remain 8-connected across the tested matrix.

The pre-registered trailing-edge prediction is therefore only partly accepted:
the point belongs to the trailing edge, but it is not connected under the D2Q9
stencil. The resolution, angle, thickness and colormap predictions are
confirmed.

## 10. Decision and stop

This is not primarily a cosmetic issue. The audit stops without changing the
builder, rasterizer, physical conversion, renderer, solver, tests or acceptance
windows.

The next phase is a dedicated NACA geometry/physical-mapping correction spec.
It must decide whether the authoritative chord presets are 10/20/40 or
20/40/80, reconcile placement, UI labels, τ/safety, force and frequency
normalization, define valid-mask gates for every offered profile/angle, and
state the focused revalidation required by the changed physical mapping.

Only after that correction is closed should SOPLO add the smooth visual contour,
the numerical-mask view and the broader trust-centred UI redesign.
